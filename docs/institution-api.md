# 銀行・証券連携（照会専用）

画面は `/institutions`。状態は常に **デモ／未接続**。実口座の残高は取らない。送金・発注・自動売買は無い。銀行・証券の照会結果をAIへ送らない。

チャットに貼られた口座番号とパスワードは使わない。ソースにも環境変数の値も置かない。

## 公開ページで確認できたこと

三菱UFJ銀行 Open API trial 一覧  
https://developer.portal.bk.mufg.jp/btmu/openapitrial/api_list

- `accounts_trial_v2` 個人API口座。残高や入出金明細等の照会。
- `accounts_trial_v1` 法人API口座。残高・入出金明細の照会。
- `customers_trial_v3` と `userinfo_trial_v1` は OpenID Connect 対応と記載。
- 振込・総合振込・給与振込・口座振替の名称はある。このアプリでは実装しない。

三菱UFJ eスマート証券（旧 auカブコム）  
https://kabu.com/api/kabucom_api.html

- 対象は法人の第三者（プロップ、助言、ツール、ロボアド、ゲーム等）。個人口座は申し込めないと記載。
- 審査（一次、面談）のあと契約。仕様書は契約後に送付。手数料無料と記載。
- 認証は OAuth 2.0。APIパスワードはマイページのAPI連携サービス利用設定。
- 照会としてページにあるもの: 注文一覧、約定一覧、建玉一覧。状態変化の配信もある。
- 注文執行・訂正・取消はページにあるが、このアプリでは実装しない。
- 現金残高の照会API名は、この公開ページに無い。作らない。

## 公開ページでは不明（推測しない）

- トークンURL、リソースURL、スコープ、レート制限。
- MUFG の利用資格、契約窓口、検証環境の有無（customers / userinfo 以外の認証方式も含む）。
- kabu のサンドボックスの有無。公開ページに記載が無い。
- このプロジェクト向けのクライアント契約が既にあるか。

## 契約するとき

1. パスワードをチャットや GitHub に書かない。漏れていれば先に変更する。
2. MUFG は開発者ポータルから trial の利用手続きを確認する。URLがポータル内に無いものは契約書面で受け取る。
3. eスマート証券は法人として申し込む。個人口座では公開ページのAPIに申し込めない。
4. 発行されたクライアントIDと秘密は、ホスティングのサーバー環境変数だけに置く。

```
MUFG_CLIENT_ID
MUFG_CLIENT_SECRET
KABU_CLIENT_ID
KABU_CLIENT_SECRET
```

値があっても、トークンURLが公開仕様に載るまではAPIを呼ばない。画面の slot は「器があるか」だけで、値は返さない。ログにも出さない。

## アクセス

- サーバー関数 `readInstitutionDesk` はアプリのログインセッションが要る。
- 操作履歴は `institution_reads` に利用者IDごと。他の利用者の行は返さない。
- デモ明細は、画面上の同意チェックのあとだけ返す。金額は ¥0、件数は 0。実口座ではない。
