# 1023 (love): consent-first local pilot

## Scope and access

`public/love/` is a dependency-free, standalone Japanese-language pilot shared with FOX OS. Serve the `public` directory over HTTP and visit `/love/` (including the trailing slash). For example, `python3 -m http.server 8000 --directory public`, then open `http://localhost:8000/love/`. On FOX OS, Vite copies `public/love/` unchanged to the build output. This does not modify the desktop, its login, or its simulated terminal. The commands here belong only to the pilot's own command field.

1023 is an application label, **not an emergency telephone number or dialable short code**. No calls are forwarded. This pilot is not staffed, monitored, or suitable for emergencies. The Japanese UI points people in immediate danger to the appropriate official services, not to this pilot.

## Implemented behavior

- Nothing starts automatically. An unchecked consent box gates `/catch msg` and the start button.
- Profile entry requires separate participant consent and an 18+ declaration each time. Profiles use generated labels, not names, contact information or IP addresses. Only profiles entered into the same page are compared. Compatible same-category profiles are listed as local condition matches, **not real connected people**.
- Relationship support is discussion only; money support is advice/program guidance only, never payments, balances, grants or promised assistance.
- The only received messages are text deliberately entered into the page. All user content is rendered with `textContent`, never HTML.
- Optional device geolocation requires separate consent and browser permission. Coordinates stay on this page. No map provider or administrator receives them. Permission errors leave all other features usable.
- `/stop catch msg`, the stop button, consent withdrawal, hiding the page and leaving it stop location watchers and erase profiles/messages/coordinates. Stale asynchronous location callbacks are ignored even if a new session has started. Stopping does not retroactively erase browser/OS history or data copied by a person.
- No local/session storage, cookies, telemetry, console logging, database, external requests, phone/IP interception or embedded contact destinations. CSP prevents app-originated network connections and form submissions. Hosting providers may independently process ordinary request metadata; this is not a promise that hosting infrastructure keeps no access logs.
- Switching tabs or minimizing the page intentionally ends the pilot session for privacy.

## Verification

Run `node --test tests/love-session.test.mjs`. Tests cover consent, compatible and incompatible matches, adult declarations, input limits, rejected phone/IP commands, full stop, location denial/unsupported devices, and late location callbacks after restart. A local DOM harness can additionally exercise app event wiring; it is not a deployed browser check.

## Production work not implemented

This pilot must not be advertised as a working help service. It has no accounts, server inbox, real user discovery, matching invitations, operator access, telephone/SMS provider, or financial transfer facility. A frontend checkbox is not identity/age verification or administrator authentication.

Before enabling real users:

1. Decide and disclose the legal operating entity, operator contact, purpose, staffed hours, emergency limitations, terms, privacy/retention policy and escalation process.
2. Add authenticated, server-authorized participant and operator access with a durable protected data store. Do not trust the FOX OS demo login for access control.
3. Implement server-side consent records, per-party connection acceptance, reporting/blocking, moderation, anti-abuse limits, age safeguards and deletion/retention controls. Do not match or expose vulnerable users based on location alone.
4. If location sharing is needed, specify who can view it and for how long, and build explicit opt-in/revocation with strict access controls. Do not locate users by phone number or IP.
5. For phone forwarding, select and authorize a communications provider. Configure the destination privately with the provider/server, not in browser code or a public repository. Display the operating entity and forwarding purpose and obtain consent before connecting. Do not request or commit credentials in chat.
6. Repair any existing FOX OS desktop build/type errors before integrating this screen into the desktop. The standalone pilot does not fix unrelated missing desktop store exports, JSX embedded in `shell.ts`, or invalid declarations in `styles.css`.
7. Complete the Vercel deployment prerequisites, connect the FOX OS repository, deploy a preview, verify desktop/mobile UI and permission-denial/stop flows, then approve any production rollout separately.

No personal name, credit line, private phone number or credential is included in this feature.
